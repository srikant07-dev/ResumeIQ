1. WHAT IS RESUMEIQ? (THE BIG PICTURE)
-------------------------------------------------------------------------------
Imagine you are applying for a software engineering job. You submit your resume, 
and within 10 minutes, you receive an automated rejection email. What happened?

Most companies use software called an ATS (Applicant Tracking System). The ATS 
scans your resume against the job description before any human recruiter ever 
looks at it. If your resume is missing specific technical skills, keywords, 
or measurable achievements, you get filtered out automatically.

Most existing "AI resume builders" or "checkers" have big flaws:
- They give random, unpredictable scores (you refresh the page and get a 
  different number).
- They hallucinate fake skills you don't have.
- They give vague advice like "make your resume more engaging".

ResumeIQ solves this completely.
ResumeIQ is an intelligent, transparent web application that compares your PDF 
resume directly against the exact job description you are targeting. 

Instead of guessing, it acts like a senior technical recruiter:
1. It reads your PDF (even if it's a scanned image).
2. It breaks down the job requirements into exact skills and keywords.
3. It uses a "Hybrid Scoring System" (part exact math, part AI analysis) to give 
   you a fair, reproducible match percentage.
4. It shows you exactly what is missing, what is matched, and provides 
   side-by-side "Before vs. After" bullet rewrites.
5. It even includes a "What-If Simulator" where you can test how adding a skill 
   would boost your score before applying!

2. HOW DOES A USER USE RESUMEIQ? (STEP-BY-STEP FLOW)
-------------------------------------------------------------------------------

Step 1: Sign Up / Login (Or Demo Mode)
- Users can create an account with email and password (powered by Supabase).
- Or, with a single click on "Explore Demo", anyone can test the entire app 
  offline without signing up or incurring any AI costs.

Step 2: Upload Resume & Paste Job Details
- The user drags and drops their resume (PDF format, up to 5MB).
- The user pastes the Job Title (e.g., "Full Stack Developer") and the 
  Job Description from LinkedIn, Indeed, or the company careers page.
- Keyboard shortcut: Users can press `Cmd + Enter` or `Ctrl + Enter` to start!

Step 3: Real-Time Diagnostic Analysis
- The backend parses the PDF and runs the 2-Stage AI analysis.
- The user sees a modern 5-stage progress indicator:
  "Extracting text -> Comparing requirements -> Scoring -> Recommendations".

Step 4: The Results Dashboard
Once the analysis finishes (usually 10 to 15 seconds), the user sees:
- Overall Match Score (0 - 100%) with a color-coded radial gauge:
  * Green (75%+): Strong Match
  * Amber (50-74%): Moderate Match / Needs Improvement
  * Red (<50%): Weak Match / High Risk of ATS rejection
- 5 Category Sub-Scores:
  1. Skills Match (35% weight)
  2. Experience Relevance (25% weight)
  3. Keyword Optimization (20% weight)
  4. Education Alignment (10% weight)
  5. Resume Quality & Formatting (10% weight)
- Skill Gap Analysis:
  * Matched Skills (e.g., Python, React)
  * Partial Skills (e.g., you have SQL, but the job asks for PostgreSQL indexing)
  * Missing Skills (e.g., Docker, Kubernetes)
- Keyword Checklist:
  * Categorized into Technical proficiencies, Soft skills, and Industry domain.
- Cognitive Contrast (Bullet Diffs):
  * Shows your weak bullet (e.g., "Worked on the backend API") side-by-side 
    with a strong, quantified rewrite (e.g., "Architected 12 FastAPI REST 
    endpoints with Redis caching, cutting latency by 42%").
  * Shows the exact line from the job description proving WHY this is needed.
- "What-If" Skill Simulator:
  * A sandbox with toggle switches. The user can toggle "Docker" to ON, and 
    instantly see their score jump in real time!
  * Includes a "⚡ Auto-Solve for 80% Match" button that automatically finds 
    the fastest route to an 80%+ score.
- Re-Evaluation & Score Delta Diffing:
  * After editing their resume, the user uploads the new PDF.
  * ResumeIQ calculates the exact score change: "+14 Overall, +20 Skills, 
    Resolved Missing: Docker, FastAPI".

3. HOW IT WORKS UNDER THE HOOD (SYSTEM ARCHITECTURE)
-------------------------------------------------------------------------------

The project is built with 4 clean layers:

1. THE FRONTEND (The Face):
   - Technology: React 19 + Vite + Tailwind CSS v4 + Phosphor Icons.
   - Design Style: "Technical-Minimal" (similar to Linear, Vercel, or Raycast).
   - Features:
     * Dark theme by default (tinted zinc palette `#09090b`).
     * Outfit font for bold titles, Geist font for clean text, Geist Mono 
       for numbers and scores.
     * Always-on Status Bar at the bottom showing system health and active state.
     * Command Palette (`Cmd + K` or `Ctrl + K`) for quick keyboard navigation.
     * Zero-lag, hardware-accelerated interactive toggles and tabs.

2. THE BACKEND (The Brain):
   - Technology: FastAPI (Python 3.11 / 3.13) + Uvicorn + Pydantic v2.
   - Why Python and FastAPI?
     * Python is the global industry standard for AI, NLP, and document parsing.
     * FastAPI is asynchronous, ultra-fast, and automatically validates all 
       incoming and outgoing data using Pydantic schemas.
     * Keeps API keys safely on the server so they never leak to the browser.

3. THE DATABASE & STORAGE (The Memory):
   - Technology: Supabase (Managed PostgreSQL + Auth + Private Storage).
   - What it stores:
     * User profiles and authentication.
     * Uploaded resume PDF files (stored securely in a private S3-compatible 
       storage bucket).
     * Analysis history and score JSON records.
   - Security: Every table is protected by PostgreSQL Row-Level Security (RLS). 
     User A can NEVER see or access User B's resumes or scores.

4. THE AI ENGINE (The Intelligence):
   - Technology: Google Gemini 3.6 Flash (`gemini-3.6-flash`) via the official 
     `google-genai` SDK.
   - Why Gemini 3.6 Flash?
     * Extreme speed (sub-10 second responses).
     * Very low cost per token.
     * Native multimodal vision capabilities (can read scanned image PDFs).
     * Strong adherence to structured JSON output.

4. THE SECRET SAUCE: WHAT MAKES RESUMEIQ TECHNICALLY UNIQUE?
-------------------------------------------------------------------------------

### Innovation 1: The Hybrid Scoring Engine
Most AI apps ask the LLM: "Give this resume a score from 1 to 100".
This is a terrible approach because LLMs are probabilistic. If you ask 5 times, 
you might get 70, 85, 62, 90, and 75 for the exact same resume!

ResumeIQ solves this with Hybrid Scoring:
- Deterministic Math (Exact Calculations in Python):
  * Skills Match Score: Calculated mathematically: 
    Score = (Matched_Count + 0.5 * Partial_Count) / Total_Required_Skills * 100
  * Keyword Score: Calculated mathematically based on the exact percentage of 
    required job keywords found in the resume.
- Validated AI Signals (Semantics & Experience):
  * Experience Relevance, Education Alignment, and Resume Quality are evaluated 
    by Gemini, but Gemini is REQUIRED to cite direct proof/quotes from the text.
  * The outputs are strictly clamped between 0 and 100 via Pydantic.
- Final Score:
  A deterministic weighted average:
  Total = (Skills * 0.35) + (Keywords * 0.20) + (Experience * 0.20) + 
          (Quality * 0.15) + (Education * 0.10)
Result: If you run the analysis again, you get consistent, defensible scores.

### Innovation 2: The Two-Stage AI Pipeline
Instead of making 4 slow sequential AI calls, or 1 massive fragile prompt that 
forgets instructions, ResumeIQ uses an optimized 2-stage pipeline:
- Stage 1 (Extract & Compare): 
  Gemini reads the resume and job description together. It extracts required 
  skills, categorizes keywords, and extracts evidence points.
- Python Math Layer: 
  FastAPI takes Stage 1 outputs and calculates the exact mathematical scores 
  in 2 milliseconds.
- Stage 2 (Recommendations): 
  Gemini receives the exact scores and gap analysis, and generates prioritized, 
  actionable advice with Before/After bullet diffs. It is strictly forbidden 
  from hallucinating fake credentials.

### Innovation 3: Dual-Tier Multimodal OCR Fallback
What happens if a candidate uploads a resume created in Canva or Photoshop where 
the text is saved as a flat picture?
- Standard PDF libraries (like PyPDF2) return empty text: `""`.
- ResumeIQ automatically detects this! If extracted text is less than 50 
  characters, it immediately triggers the Multimodal Gemini Vision fallback.
- Gemini "looks" at the document visually, extracts all text with OCR, and 
  continues the analysis without failing.

### Innovation 4: Resume Revision & Score Delta Diffing
Job improvement is iterative. ResumeIQ lets users click "Re-evaluate with New 
Resume". The backend runs the new resume against the same job description, 
and computes a mathematical diff:
- `overall_delta`: e.g. +14
- `skills_delta`: e.g. +20
- `resolved_missing_skills`: e.g. ["Docker", "FastAPI"]
- `newly_matched_skills`: e.g. ["Docker", "FastAPI"]
The frontend renders a visual comparison modal showing the candidate's exact 
progress.

5. SECURITY & DEFENSE-IN-DEPTH ARCHITECTURE
-------------------------------------------------------------------------------

ResumeIQ was engineered to meet production security standards:

1. Double-Layer User Isolation:
   - Layer 1 (API): FastAPI inspects the Supabase JWT Bearer token on every 
     request, verifies the cryptographic signature, and extracts `user_id`. 
     Every single database query explicitly filters:
     `.eq("user_id", authenticated_user_id)`
   - Layer 2 (Database): PostgreSQL Row-Level Security (RLS) policies enforce 
     that even if an API bug occurred, the database itself rejects any attempt 
     to read or write another user's rows.

2. PDF Security & Magic-Byte Validation:
   - Malicious users might rename an `.exe` or script to `resume.pdf`.
   - ResumeIQ validates the file in Python:
     * Checks file size limit (<= 5MB).
     * Checks extension (`.pdf`).
     * Inspects the first 4 binary bytes of the file to guarantee it starts 
       with `%PDF-`.

3. Error Sanitization in Production:
   - In production (`DEMO_MODE=false`), the global exception handlers in 
     FastAPI strip all raw internal error traces, database table names, and 
     stack traces, returning safe generic messages to prevent information 
     disclosure.

4. Production-Safe CORS:
   - In production, cross-origin requests are strictly limited to the deployed 
     frontend domain (e.g. Netlify/Vercel).

6. HOW TO EXPLAIN THIS PROJECT IN AN INTERVIEW
-------------------------------------------------------------------------------

When an interviewer says: "Tell me about a project you've built."

### The 30-Second Elevator Pitch:
"I built ResumeIQ, a production-grade full-stack SaaS application that helps 
job seekers optimize their resumes for specific job descriptions. I built it 
with React 19, Tailwind CSS v4, FastAPI, Supabase, and Google Gemini AI. 

What makes it unique is that instead of relying on opaque, hallucinated AI 
scores, I engineered a Hybrid Scoring Engine that combines deterministic math 
for skills and keywords with grounded LLM semantic analysis. It also includes 
an interactive 'What-If' simulator and dual-tier OCR for scanned PDFs."

### The Deep-Dive Follow-Up Questions (Interview Questions & Answers):

Q1: Why did you decouple React and FastAPI instead of using Next.js?
Answer:
"I wanted clean architectural boundaries. FastAPI is asynchronous, lightweight, 
and native to Python, which gave me direct access to Python's AI and document 
ecosystem (Google GenAI SDK, PyPDF2, Pydantic). Decoupling also ensures server 
secrets like the Supabase service-role key and Gemini API key can never 
accidentally leak into client JavaScript bundles."

Q2: How did you solve LLM hallucinations in scoring?
Answer:
"I realized that LLMs are great at semantic reasoning but terrible at 
reproducible math. So I separated the responsibilities:
- Skills and keywords are calculated deterministically in Python using set 
  intersections.
- The LLM is used only for qualitative evaluation (experience relevance and 
  bullet strength), and it is required to provide direct quote citations from 
  the source text.
- Pydantic validates and clamps every score between 0 and 100 before computing 
  the final weighted score. This makes the scores consistent, explainable, 
  and trustworthy."

Q3: How do you handle scanned or image-based resumes?
Answer:
"Traditional PDF text extractors return empty strings when reading flattened 
or scanned PDFs. I built a dual-tier parsing pipeline in `pdf_parser.py`:
It first attempts high-speed extraction using PyPDF2. If the extracted text 
is under 50 characters, it automatically triggers a fallback to Google Gemini's 
multimodal vision capability, which performs OCR and extracts the text cleanly."

Q4: How did you ensure the frontend feels fast and responsive?
Answer:
"I followed a Technical-Minimal design contract inspired by Linear and Vercel. 
I eliminated tab-switching lag by avoiding artificial animation delays and font 
weight shifts that cause layout reflow. For the Skill Simulator, score updates 
run with CSS hardware-accelerated transforms, giving users instant 60fps 
feedback. I also added global keyboard shortcuts like `Cmd+K` for power 
navigation."

Q5: What was your testing strategy?
Answer:
"I implemented comprehensive automated testing across both layers:
- Backend: 85 Pytest tests covering boundary conditions, adversarial inputs 
  (malformed tokens, oversized files, spoofed PDFs), OCR fallback, and scoring.
- Frontend: 65 Vitest tests across 18 test suites covering component rendering, 
  state synchronization, keyboard shortcuts, and full user workflows.
Overall, 150 automated tests with 100% pass rate."
